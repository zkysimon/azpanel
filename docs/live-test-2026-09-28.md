经用户授权，仅对随机命名的临时资源进行写操作。使用新版 Fastify API 的登录、接入、任务队列与 Azure 适配层；本地数据库、密钥及 VM 密码均只存在于测试进程内存。

## 环境

- 订阅：Azure for Students，Enabled。
- 区域：eastasia。
- 临时规格：Standard_B1s（1 vCPU / 1 GiB），Ubuntu 24.04 Gen2，30 GiB Standard SSD。

- ARM 请求串行，间隔 2.5 秒；没有压测或批量创建。
- 原资源：2 个资源组、1 台 `proxyhk`（Standard_B1s）。

## 实测发现与修复

1. **Ubuntu 24.04 SKU 错误**：旧配置 `24_04-lts` 无效。真实镜像目录返回 `server`；已改为 `Canonical:ubuntu-24_04-lts:server:latest`，并添加回归断言。
2. **资源组大小写**：Azure VM 返回的 resource ID 中资源组段为大写。测试脚本原先区分大小写，导致创建成功却误报未同步；现已按 Azure 语义不区分大小写匹配。
3. **删除轮询的网络错误**：删除请求已被 Azure 接收，但后续查询断连，面板任务报错。独立读取确认资源实际已全部删除。适配层补齐 GET 网络故障有限重试，不重放 DELETE / POST / PUT。
